# Wrap up: close this chat for good

Goal: this chat can be deleted with nothing lost. What matters goes into the files; every attachment is somewhere durable; the conversation itself is kept word for word if it's worth keeping. A deleted chat is gone, and there is no getting it back, so nothing is "safe to delete" until every step below is done and seen.

1. Read the files fresh. Same as a hand off: fetch the current version of each file before you change it (guide, section 7). Keep lines you don't recognize; another chat wrote them.

2. Sweep and file everything durable. Same as handoff.md, step 2: decisions to log.md, people to people.md, areas to areas.md, tasks to now.md, facts and preferences to profile.md. Ask before each change ("Your files say X. Today you said Y. Update areas.md?") and wait for the yes; a no means the file stays as it is. Whole file, built on the current version, only what this conversation changed, say what changed, one file at a time. Half-done work gets a status line in now.md.

3. Every attachment, placed. A deleted chat takes its attachments with it. List everything uploaded to this chat and everything you made in it. Small text goes to inbox/ (one file, named by date) or the lake. Photos, PDFs and exports get saved by them to their phone or Drive, and a file says where. Not "safe to delete" while anything exists only here. If a hand off earlier in this chat already placed some of them, check they're there and list them; don't duplicate.

4. The transcript, only if they keep conversations. What was decided and learned is already in the files from step 2; that happens whether or not a transcript is kept, and saying no here never loses it. If they said no to keeping conversations at setup and still feel that way, skip this step. If they keep them, and this one is worth keeping word for word, give them the full text as one file: both sides, in order, their words exactly as typed, mistakes included, never tidied. Three header lines at the top: the date, the subject in one line, and the files (each attachment, its name and where it now lives, or "none"). Name it YYYY-MM-DD-subject.md. It goes in the lake. If they've changed their mind since setup and want to start keeping conversations, offer to make the lake now (guide, section 9): a second private repository just for transcripts, never connected to the assistant, so the five files stay small while the originals pile up safely. Until it exists, the file can wait in inbox/. The transcript is the backstop, not the summary: don't boil it down.

5. If work is unfinished, the continuation note from handoff.md, step 5, so the next chat can pick up.

6. Say it's safe. A short checklist: which files changed, every attachment and where it went, the transcript's name and where it is, and the line "Safe to delete." If anything couldn't be placed, say which, and don't say safe.

Two things that go wrong. A wrapped chat keeps going: if it does, sweep again and add to the transcript before it's deleted; "filed" is not "finished". And "saved" that wasn't: never say a file is saved unless the save worked and they've seen it on GitHub.
